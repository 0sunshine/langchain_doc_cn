Deep Agents 可与任何支持 [tool calling](/oss/javascript/langchain/models#tool-calling) 的 [LangChain chat model](/oss/javascript/langchain/models) 配合使用。

## Supported models

用 `provider:model` 格式指定 models（例如 `google_genai:gemini-3.5-flash`、`openai:gpt-5.4` 或 `anthropic:claude-sonnet-4-6`）。provider prefix 会选择 LangChain integration，冒号后面的所有内容会作为 model identifier 传递给该 provider。有效 provider strings 请参阅 [`init_chat_model`](https://reference.langchain.com/javascript/langchain/chat_models/universal/initChatModel) 的 `model_provider` 参数。provider-specific configuration 请参阅 [chat model integrations](/oss/javascript/integrations/chat)。

model identifier 必须匹配 provider 期望的格式。有些 providers 使用 `gpt-5.4` 这样的简单名称；有些使用 namespaced IDs 或 deployment paths，例如 `zai-org/GLM-5.1`，因此完整的 Deep Agents 字符串会是 `baseten:zai-org/GLM-5.1`。请查看 provider 的 model catalog 或 integration docs 获取当前 identifiers。

### Suggested models

这些 models 在 [Deep Agents eval suite](https://github.com/langchain-ai/deepagents/tree/main/libs/evals#readme) 上表现良好；该 suite 测试基础 agent operations。通过这些 evals 是在更长、更复杂任务上取得强表现的必要条件，但并不充分。

| Provider | Models |
|----------|--------|
| [Google](/oss/javascript/integrations/providers/google) | `gemini-3.1-pro-preview`, `gemini-3-flash-preview` |
| [OpenAI](/oss/javascript/integrations/providers/openai) | `gpt-5.4`, `gpt-4o`, `gpt-5.4`, `o4-mini`, `gpt-5.2-codex`, `gpt-4o-mini`, `o3` |
| [Anthropic](/oss/javascript/integrations/providers/anthropic) | `claude-opus-4-6`, `claude-opus-4-5`, `claude-sonnet-4-6`, `claude-sonnet-4`, `claude-sonnet-4-5`, `claude-haiku-4-5`, `claude-opus-4-1` |
| Open-weight | `GLM-5`, `Kimi-K2.5`, `MiniMax-M2.5`, `qwen3.5-397B-A17B`, `devstral-2-123B` |



Open-weight models 可通过 [OpenRouter](/oss/javascript/integrations/chat/openrouter)、[Fireworks](/oss/javascript/integrations/chat/fireworks) 或 [Ollama](/oss/javascript/integrations/chat/ollama) 等 providers 使用。

## 配置 model parameters



以 `provider:model` 格式向 [`createDeepAgent`](https://reference.langchain.com/javascript/deepagents/agent/createDeepAgent) 传入 model string，或传入 configured model instance 以获得完全控制。底层会通过 [`init_chat_model`](https://reference.langchain.com/javascript/langchain/chat_models/universal/initChatModel) 解析 model strings。


要配置 model-specific parameters，请使用 [`init_chat_model`](https://reference.langchain.com/javascript/langchain/chat_models/universal/initChatModel)，或直接实例化 provider model class：



<CodeGroup>
    ```typescript initChatModel
    import { initChatModel } from "langchain/chat_models/universal";
    import { createDeepAgent } from "deepagents";

    const model = await initChatModel("google_genai:gemini-3.5-flash", {
        reasoningEffort: "medium",  // [!code highlight]
    });
    const agent = createDeepAgent({ model });
    ```

    ```typescript Provider package
    import { ChatGoogle } from "@langchain/google";
    import { createDeepAgent } from "deepagents";

    const model = new ChatGoogle({
        model: "gemini-3.1-pro-preview",
        reasoningEffort: "medium",  // [!code highlight]
    });
    const agent = createDeepAgent({ model });
    ```
</CodeGroup>


<Note>
    可用 parameters 会因 provider 而异。provider-specific configuration options 请参阅 [chat model integrations](/oss/javascript/integrations/chat) 页面。
</Note>

### Provider profiles

[`ProviderProfile`](/oss/javascript/deepagents/profiles#provider-profiles) 会打包 initialization parameters；当你在创建 deep agent 时提供 `provider:model` 字符串，它们会被应用。若你通过 [`init_chat_model`](https://reference.langchain.com/javascript/langchain/chat_models/universal/initChatModel) 传入 preconfigured model，则不会应用。

你可以在两个层级注册，二者可共存：

- **Provider level**：裸 provider key，例如 `"openai"`，适用于 `openai` provider 的每个 model。
- **Model level**：`provider:model` key，例如 `"openai:gpt-5.4"`，只适用于该具体 model，并会 merge 在任何匹配 provider-level profile 之上。

```python
from deepagents import ProviderProfile, register_provider_profile

# Provider-wide default: every openai model gets temperature=0.
register_provider_profile(
    "openai",
    ProviderProfile(init_kwargs={"temperature": 0}),
)

# Model-level override: gpt-5.4 additionally gets a specific reasoning effort.
# Inherits temperature=0 from the provider-level profile above.
register_provider_profile(
    "openai:gpt-5.4",
    ProviderProfile(init_kwargs={"reasoning_effort": "medium"}),
)
```

完整 field list、merge semantics 和 plugin packaging 请参阅 [Profiles](/oss/javascript/deepagents/profiles)。

<Tip>
    若要塑造 model 构建完成后 *agent* 的行为，请使用 [harness profile](/oss/javascript/deepagents/profiles#harness-profiles)。
</Tip>

## 在 runtime 选择 model

如果你的应用允许用户选择 model（例如在 UI 中使用 dropdown），请使用 [middleware](/oss/javascript/langchain/middleware) 在 runtime 替换 model，而无需重建 agent。



```typescript
import { initChatModel, createMiddleware } from "langchain";
import { createDeepAgent } from "deepagents";
import * as z from "zod";

const contextSchema = z.object({
  model: z.string(),
});

const configurableModel = createMiddleware({
  name: "ConfigurableModel",
  wrapModelCall: async (request, handler) => {
    const modelName = request.runtime.context.model;
    const model = await initChatModel(modelName);
    return handler({ ...request, model });
  },
});

const agent = await createDeepAgent({
  model: "google_genai:gemini-3.5-flash",
  middleware: [configurableModel],
  contextSchema,
});

// Invoke with the user's model selection
const result = await agent.invoke(
  { messages: [{ role: "user", content: "Hello!" }] },
  { context: { model: "openai:gpt-5.4" } },
);
```


<Tip>
    关于更多 dynamic model patterns（例如基于 conversation complexity 或 cost optimization 路由），请参阅 LangChain agents guide 中的 [Dynamic model](/oss/javascript/langchain/models#dynamic-model-selection)。
</Tip>
