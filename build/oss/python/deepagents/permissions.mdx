使用声明式 permission rules 控制 agent 可以读取或写入哪些文件和目录。向 `permissions=` 传入 rules 列表后，agent 内置的 filesystem tools 会遵守这些规则。

<Note>
    Permissions 需要 `deepagents>=0.5.2`。
</Note>




Permissions 只适用于内置 filesystem tools（`ls`、`read_file`、`glob`、`grep`、`write_file`、`edit_file`）。访问 filesystem 的 custom tools 和 MCP tools 不在覆盖范围内。Permissions 也不适用于 [sandbox backends](/oss/python/deepagents/sandboxes)，因为它们通过 `execute` tool 支持任意 command execution。

<Tip>
当你需要对内置 filesystem tools 使用 **path-based allow/deny rules** 时，请使用 `permissions`。当你需要 custom validation logic（rate limiting、audit logging、content inspection），或需要控制 custom tools 时，请使用 [backend policy hooks](/oss/python/deepagents/backends#add-policy-hooks)。
</Tip>

## 基本用法 {#basic-usage}

向 [`create_deep_agent`](https://reference.langchain.com/python/deepagents/graph/create_deep_agent) 传入 [`FilesystemPermission`](https://reference.langchain.com/python/deepagents/middleware/permissions/FilesystemPermission) rules 列表。Rules 会按声明顺序求值。第一条匹配 rule 生效。如果没有 rule 匹配，则允许该操作。

<PermissionsBasicPy />





## 规则结构 {#rule-structure}

每个 `FilesystemPermission` 有三个字段：

| 字段 | 类型 | 描述 |
|---|---|---|
| `operations` | `list["read" \| "write"]` | 这条 rule 适用的 operations。`"read"` 覆盖 `ls`、`read_file`、`glob`、`grep`。`"write"` 覆盖 `write_file`、`edit_file`。 |
| `paths` | `list[str]` | 用于匹配 file paths 的 glob patterns（例如 `["/workspace/**"]`）。支持用于 recursive matching 的 `**`，以及用于 alternation 的 `{a,b}`。 |
| `mode` | `"allow" \| "deny"` | 是否允许或拒绝匹配的 operations。默认是 `"allow"`。 |

Rules 使用 first-match-wins evaluation：第一条 `operations` 和 `paths` 与当前调用匹配的 rule 决定结果。如果没有 rule 匹配，则调用被**允许**（permissive default）。

## Subagent 权限 {#subagent-permissions}

[Subagents](/oss/python/deepagents/subagents) 默认继承 parent agent 的 permissions。要给 subagent 不同 permissions，请在它的 spec 中设置 `permissions` 字段。这会完全**替换** parent rules。

## Composite backends

当使用带 sandbox default 的 [`CompositeBackend`](https://reference.langchain.com/python/deepagents/backends/composite/CompositeBackend) 时，每个 permission path 都必须 scoped under 一个已知 route prefix。Sandboxes 支持任意 command execution，因此仅靠 path-based restrictions 无法阻止通过 shell commands 访问 filesystem。将 permissions scoped 到 route-specific [backends](/oss/python/deepagents/backends) 可以避免这个冲突。
