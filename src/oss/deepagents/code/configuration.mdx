Deep Agents Code 会把 configuration 存储在 `~/.deepagents/` directory 中。主要 config files 包括：

| 文件 | 格式 | 用途 |
|------|--------|---------|
| `config.toml` | TOML | Model defaults、provider settings、constructor params、profile overrides、themes、update settings、MCP trust store |
| `.env` | Dotenv | Global API keys 和 secrets |
| `hooks.json` | JSON | 对 Deep Agents Code lifecycle events 的 external tool subscriptions |
| `.mcp.json` | JSON | Global MCP server definitions |

<Note>
    `~/.deepagents/.state/` 下的 files 保存 per-machine Deep Agents Code state，并由系统自动管理。
</Note>

## Provider 凭证 {#provider-credentials}

对于每个 provider，Deep Agents Code 会按顺序检查两个 credential sources：

1. **Stored keys** - 通过 `/auth` 输入并在本地持久化。
2. **Environment variables** - `OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`GOOGLE_API_KEY` 等，以及带 [`DEEPAGENTS_CODE_`](#deepagents_code_-prefix) prefix 的同名 variables 和从 [`.env` files](#environment-variables) 加载的 keys。

同一个 provider 同时存在 stored key 和 env-var key 时，stored key 总是优先。

### 使用 `/auth`（推荐） {#use-/auth-recommended}

在任意 session 中打开 credential manager：

```txt
/auth
```

manager 会列出 Deep Agents Code 已知的每个 LLM provider，标记已经有 key 的 providers，并允许你 inline paste、rotate 或 clear credentials。每个 provider 会显示为以下状态之一：

| 标签 | 含义 |
|-------|---------|
| `credentials set` | 可用 stored key 或 env-var key |
| `! missing OPENAI_API_KEY` | 指定 env var 未设置且没有 stored key；选择该行即可粘贴 key |
| `local provider` | 不需要 credentials（例如 local Ollama） |
| `implicit auth` | Credentials 是 implicit 的（例如 Vertex AI Application Default Credentials） |
| `custom auth` | 由 `class_path` provider 自己管理 auth（mTLS、JWT、custom headers） |

在某一行按 Enter 可粘贴 key，也可以使用该行的 delete affordance 清除 existing key。Saved keys 会 atomic write，并跨 sessions 和 `/reload` 持久化。

<Note>
    Keys 仅 scoped 到这台机器上的你的 user account。Deep Agents Code 只会把它们发送给 configured provider 的 API，不会发送到其他地方。
</Note>

`/auth` 只管理 **LLM provider** credentials。`TAVILY_API_KEY`（web search）和 `LANGSMITH_API_KEY`（tracing）等 tool credentials 会从 environment 读取。请[在 `~/.deepagents/.env` 或 shell 中设置它们](#environment-variables)。

### 环境变量（CI 和 headless） {#environment-variables-ci-and-headless}

对于 non-interactive runs、CI/CD pipelines 或任何无法使用 TUI 的地方，请 export provider 的 env var，或写入 `~/.deepagents/.env`：

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
export OPENAI_API_KEY="sk-..."
```

loading order、`DEEPAGENTS_CODE_` prefix 和 per-project overrides 请参阅下面的 [Environment variables](#environment-variables)。

## 环境变量 {#environment-variables}

Deep Agents Code 会从 dotenv files 加载 environment variables，因此你不需要在 shell profile 中 `export` API keys，也不需要在各 projects 中重复 `.env` files。

### 加载顺序和优先级 {#loading-order-and-precedence}

startup 时会加载两个 `.env` files：

1. **Project `.env`** - 当前 working directory 中的 `.env` file（如果存在）
2. **Global `~/.deepagents/.env`** - 一个所有 projects 共享的 fallback file

实际 precedence 是：**shell environment > project `.env` > global `.env`**。shell 中已经设置的 values 永远不会被覆盖，包括 `/reload` 时也是如此。

### `DEEPAGENTS_CODE_` 前缀 {#deepagents_code_-prefix}

所有 Deep Agents Code-specific environment variables 都使用 `DEEPAGENTS_CODE_` prefix（例如 `DEEPAGENTS_CODE_AUTO_UPDATE`、`DEEPAGENTS_CODE_DEBUG`）。完整列表请参阅 [environment variable reference](#environment-variable-reference)。

这个 prefix 也可以作为 Deep Agents Code 读取的任意 environment variable 的 override mechanism，包括 third-party credentials。Deep Agents Code 会先检查 `DEEPAGENTS_CODE_{NAME}`，再 fallback 到 `{NAME}`：

```bash title="~/.deepagents/.env"
# Override OPENAI_API_KEY only for Deep Agents Code, without affecting other tools
DEEPAGENTS_CODE_OPENAI_API_KEY=sk-cli-only

# Block a shell-exported key within Deep Agents Code by setting the prefixed var to empty
DEEPAGENTS_CODE_ANTHROPIC_API_KEY=
```

在 `/reload` 时，Deep Agents Code 会重新读取 `.env` files 并拾取 prefixed values，因此你可以不重启就 rotate keys。

### 示例 {#example}

把 API keys 一次性存到 `~/.deepagents/.env`：

```bash
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...
LANGSMITH_API_KEY=lsv2_...
TAVILY_API_KEY=tvly-...

# If OPENAI_API_KEY is already exported in your shell for other tools,
# use the prefix to give Deep Agents Code its own key without conflict
DEEPAGENTS_CODE_OPENAI_API_KEY=sk-cli-only-...
```

需要 per-project override 时，在 project directory 中放置 `.env`。

### 启用 Tavily web search {#enable-web-search-with-tavily}

built-in `web_search` tool 使用 [Tavily](https://tavily.com)。在你提供 key 之前，Deep Agents Code 会在 startup 时显示 "Web search disabled - `TAVILY_API_KEY` is not set" notification。与 model provider keys 不同，Tavily **不** 由 `/auth` 管理，而是直接从 environment 读取。

<Steps>
    <Step title="获取 key">
        在 [tavily.com](https://tavily.com) 注册并复制 key（它以 `tvly-` 开头）。free tier 足以满足大多数 Deep Agents Code 用法。
    </Step>

    <Step title="添加到你的环境">
        将 key 添加到 `~/.deepagents/.env`，让每个 session 都能拾取：

        ```bash title="~/.deepagents/.env"
        TAVILY_API_KEY=tvly-...
        ```

        或者在 shell 中 export，仅用于一次性 session：

        ```bash
        export TAVILY_API_KEY=tvly-...
        ```

        Shell exports 的优先级高于 `.env` values（参见 [Loading order and precedence](#loading-order-and-precedence)）。如果只想把 key scoped 到 Deep Agents Code，而不影响其他读取 `TAVILY_API_KEY` 的 tools，请使用 [`DEEPAGENTS_CODE_` prefix](#deepagents_code_-prefix)：`DEEPAGENTS_CODE_TAVILY_API_KEY=tvly-...`。
    </Step>

    <Step title="重新加载或重启">
        在 existing session 中运行 `/reload` 重新读取 `.env` files。下一次 launch 时，"Web search disabled" notification 会消失，agent 就可以调用 `web_search`。
    </Step>
</Steps>

## 配置文件 {#config-file}

`~/.deepagents/config.toml` 可用于自定义 model providers、设置 defaults，以及向 model constructors 传递额外 parameters。

### 默认和最近使用的 model {#default-and-recent-model}

```toml
[models]
default = "ollama:qwen3:4b"             # your intentional long-term preference
recent = "google_genai:gemini-3.5-flash"   # last /model switch (written automatically)
```

`[models].default` 总是优先于 `[models].recent`。`/model` command 只会写入 `[models].recent`，因此你配置的 default 不会被 mid-session switches 覆盖。要移除 default，请使用 `/model --default --clear`，或从 config file 删除 `default` key。

### 默认和最近使用的 agent {#default-and-recent-agent}

```toml
[agents]
default = "backend-dev"  # your intentional long-term preference (Ctrl+S in /agents picker)
recent = "frontend-dev"  # last /agents switch (written automatically)
```

`[agents].default` 总是优先于 `[agents].recent`。在 `/agents` picker 中按 `Enter` 选择 agent 会写入 `recent`；在 highlighted row 上按 `Ctrl+S` 会把它 pin 为 `default`。再次在同一行按 `Ctrl+S` 会清除 default。

显式 `-a`/`--agent` 总是覆盖两者，`-r`/`--resume` 会绕过两者，以恢复 thread 原始 agent。相关 flags 请参阅 [Command reference](/oss/deepagents/code/overview#command-reference)。

### Provider 配置 {#provider-configuration}

每个 provider 都是 `[models.providers]` 下的 TOML table：

```toml
[models.providers.<name>]
models = ["gpt-4o"]
api_key_env = "OPENAI_API_KEY"
base_url = "https://api.openai.com/v1"
class_path = "my_package.models:MyChatModel"
enabled = true

[models.providers.<name>.params]
temperature = 0
max_tokens = 4096

[models.providers.<name>.params."gpt-4o"]
temperature = 0.7
```

Providers 支持以下 configuration options：

<ResponseField name="models" type="string[]" post={["optional"]}>
    要在该 provider 的 interactive `/model` switcher 中显示的 model names 列表。对于已经随附 model profiles 的 providers，这里添加的 names 会与 bundled ones 一起显示，适合尚未加入 package 的新发布 models。对于 [arbitrary providers](#arbitrary-providers)，这个列表是 switcher 中 models 的唯一来源。

    这里列出的 models 会 **bypass** profile-based [filtering criteria](/oss/deepagents/code/providers#which-models-appear-in-the-switcher)，并始终出现在 switcher 中。因此，对于因为 profile 缺少 `tool_calling` support 或尚不存在 profile 而被排除的 models，这是推荐的暴露方式。

    该 key 是 optional。无论 model 是否出现在 switcher 中，你都可以直接把任意 model name 传给 `/model` 或 `--model`；provider 会在 request time 验证 name。
</ResponseField>

<ResponseField name="api_key_env" type="string" post={["optional"]}>
    保存 API key 的 environment variable **名称**（例如 `"OPENAI_API_KEY"`），不是 key 本身。Deep Agents Code 会在 startup 时从该 env var 读取 credential，用于在创建 model 前验证 access。多数 chat model packages 会自动读取默认 env var。每个 provider 检查的 variable 请参阅 [Provider reference](/oss/deepagents/code/providers#provider-reference) table。
</ResponseField>

<ResponseField name="base_url" type="string" post={["optional"]}>
    如果 provider 支持，覆盖它使用的 base URL。更多信息请参阅 provider package 的 [reference docs](https://reference.langchain.com/python/integrations/)。
</ResponseField>

<ResponseField name="params" type="object" post={["optional"]}>
    转发给 model constructor 的额外 keyword arguments。Flat keys（例如 `temperature = 0`）会应用到该 provider 的每个 model。Model-keyed sub-tables（例如 `[params."gpt-4o"]`）只覆盖对应 model 的 individual values；merge 是 shallow 的（冲突时 model 胜出）。

    不要把 credentials（例如 `api_key`）放进 `params`。请使用 [`api_key_env`](#provider-configuration) 指向 environment variable。
</ResponseField>

<ResponseField name="profile" type="object" post={["optional"]}>
    (Advanced) 覆盖 model runtime [profile](/oss/langchain/models#model-profiles) 中的字段（例如 `max_input_tokens`）。Flat keys 应用于该 provider 的每个 model。Model-keyed sub-tables（例如 `[profile."claude-sonnet-4-5"]`）只覆盖对应 model 的 individual values；merge 是 shallow 的（冲突时 model 胜出）。这些 overrides 会在 model 创建后应用，因此会影响 context-limit display、auto-summarization，以及其他读取 profile 的功能。
</ResponseField>

<ResponseField name="class_path" type="string" post={["optional"]}>
    用于 [arbitrary model](#arbitrary-providers) providers。格式为 `module.path:ClassName` 的 fully-qualified Python class。设置后，Deep Agents Code 会为 provider `<name>` 直接 import 并实例化该 class。该 class 必须是 `BaseChatModel` subclass。
</ResponseField>

<ResponseField name="enabled" type="boolean" default="true" post={["optional"]}>
    控制该 provider 是否出现在 `/model` selector 中。设置为 `false` 可以隐藏从 installed package 自动发现的 provider（例如你不想让它挤占 switcher 的 transitive dependency）。disabled provider 仍可通过 `/model provider:model` 或 `--model` 直接使用。
</ResponseField>

### Model constructor 参数 {#model-constructor-params}

任何 provider 都可以使用 `params` table 向 model constructor 传递额外 arguments：

```toml
[models.providers.ollama.params]
temperature = 0
num_ctx = 8192
```

#### 按 model 覆盖 {#per-model-overrides}

如果某个特定 model 需要不同 params，请在 `params` 下添加 model-keyed sub-table，这样不用复制整个 provider config 就能覆盖 individual values：

```toml
[models.providers.ollama]
models = ["qwen3:4b", "llama3"]

[models.providers.ollama.params]
temperature = 0
num_ctx = 8192

[models.providers.ollama.params."qwen3:4b"]
temperature = 0.5
num_ctx = 4000
```

在这个配置下：

* `ollama:qwen3:4b` 获得 `{temperature: 0.5, num_ctx: 4000}` - model overrides 胜出。
* `ollama:llama3` 获得 `{temperature: 0, num_ctx: 8192}` - 没有 override，只使用 provider-level params。

merge 是 shallow 的：model sub-table 中出现的 key 会替换 provider-level params 中的同名 key，而只存在于 provider level 的 keys 会保留。

<Tip>
    如果只是做一次性调整，不想编辑 `config.toml`，可以在 launch 时通过 `--model-params` 传入 JSON object，或在 session 中用 `/model` 设置。CLI flags 的优先级高于 config file。语法和 provider-specific examples 请参阅 providers 页面上的 [Model parameters](/oss/deepagents/code/providers#model-parameters)。
</Tip>

### Profile overrides（高级） {#profile-overrides-advanced}

覆盖 model runtime profile 中的字段，以改变 Deep Agents Code 对 model capabilities 的理解。最常见用途是降低 `max_input_tokens`，更早触发 auto-summarization，这对 testing 或限制 context usage 很有用：

```toml
# Apply to all models from this provider
[models.providers.anthropic.profile]
max_input_tokens = 4096
```

Per-model sub-tables 与 `params` 工作方式相同：冲突时 model-level value 胜出：

```toml
[models.providers.anthropic.profile]
max_input_tokens = 4096

# This model gets a higher limit
[models.providers.anthropic.profile."claude-sonnet-4-5"]
max_input_tokens = 8192
```

Profile overrides 会在 model 创建后 merge 到 model profile 中。任何读取 profile 的功能，例如 status bar 中的 context-limit display、auto-summarization thresholds、capability checks，都会看到被覆盖后的 values。

#### 使用 `--profile-override` 的 CLI profile overrides（高级） {#cli-profile-overrides-with-profile-override-advanced}

如果想在 runtime 覆盖 model profile fields，而不编辑 config file，请通过 `--profile-override` 传入 JSON object：

```bash
dcode --profile-override '{"max_input_tokens": 4096}'

# Combine with --model
dcode --model google_genai:gemini-3.5-flash --profile-override '{"max_input_tokens": 4096}'

# In non-interactive mode
dcode -n "Summarize this repo" --profile-override '{"max_input_tokens": 4096}'
```

这些会叠加在 config file profile overrides 之上（CLI 胜出）。优先级链为：model default &lt; config.toml profile &lt; CLI `--profile-override`。

`--profile-override` values 会在 mid-session `/model` hot-swaps 之间保持；切换 models 后会把 override 重新应用到新 model。

### 自定义 base URL {#custom-base-url}

一些 provider packages 接受 `base_url` 来覆盖 default endpoint。例如，`langchain-ollama` 通过 underlying `ollama` client 默认使用 `http://localhost:11434`。要指向其他地址，请在 configuration 中设置 `base_url`：

```toml
[models.providers.ollama]
base_url = "http://your-host-here:port"
```

compatibility information 和其他 considerations 请参阅 provider reference documentation。

### 兼容 APIs {#compatible-apis}

对于暴露 OpenAI 或 Anthropic wire-compatible APIs 的 providers，你可以使用现有的 `langchain-openai` 或 `langchain-anthropic` packages，并把 `base_url` 指向 provider endpoint：

```toml
[models.providers.openai]
base_url = "https://api.example.com/v1"
api_key_env = "EXAMPLE_API_KEY"
models = ["my-model"]
```

```toml
[models.providers.anthropic]
base_url = "https://api.example.com"
api_key_env = "EXAMPLE_API_KEY"
models = ["my-model"]
```

<Note>
    provider 在 official spec 之上添加的 features 不会被捕获。如果 provider 提供 dedicated LangChain integration package，请优先使用它。
</Note>

<Warning>
    OpenAI provider 默认使用 [Responses API](https://platform.openai.com/docs/api-reference/responses)，大多数 OpenAI-compatible gateways 并未实现该 API。如果你的 provider 只支持 Chat Completions API，调用很可能失败。请显式禁用 Responses API：

    ```toml
    [models.providers.openai.params]
    use_responses_api = false
    ```
</Warning>

### 向交互式 switcher 添加 models {#adding-models-to-the-interactive-switcher}

一些 providers（例如 `langchain-ollama`）不会捆绑 model profile data（完整列表请参阅 [Provider reference](/oss/deepagents/code/providers#provider-reference)）。这种情况下，interactive `/model` switcher 不会列出该 provider 的 models。你可以在 config file 中为 provider 定义 `models` list 来补齐：

```toml
[models.providers.ollama]
models = ["llama3", "mistral", "codellama"]
```

现在 `/model` switcher 会包含 Ollama section，并列出这些 models。

这是完全 optional 的。你始终可以通过直接指定完整名称切换到任意 model：

```txt
/model ollama:llama3
```

<Note>
    当安装了 `langchain-ollama` 且 daemon 可访问时，Deep Agents Code 会 auto-discover 本地 pulled models，并把它们 merge 到 switcher 中，不需要 `models` list。pull 新 models 后运行 `/reload` 刷新，或设置 `DEEPAGENTS_CODE_OLLAMA_DISCOVERY=0` 退出该行为。
</Note>

### 任意 providers {#arbitrary-providers}

你可以通过 `class_path` 使用任何 [LangChain `BaseChatModel`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.BaseChatModel) subclass。Deep Agents Code 会直接 import 并实例化 class，不需要 built-in provider package。

```toml
[models.providers.my_custom]
class_path = "my_package.models:MyChatModel"
api_key_env = "MY_API_KEY"
base_url = "https://my-endpoint.example.com"

[models.providers.my_custom.params]
temperature = 0
max_tokens = 4096
```

`api_key_env` 和 `base_url` 是 optional。`class_path` providers 应自行处理 authentication，这在 model 使用 custom auth（JWT tokens、proprietary headers、mTLS 等）而不是 standard API key 时很有用：

```toml
[models.providers.xyz]
class_path = "abc.integrations.deepagents:DeepAgentsXYZChat"
models = ["abc-xyz-1"]

[models.providers.xyz.params]
bypass_auth = true
temperature = 0
```

使用该 config 后，可以通过 `/model xyz:abc-xyz-1` 或 `--model xyz:abc-xyz-1` 切换到 model。

<Note>
    Deep Agents Code 需要 **tool calling** support。如果 custom model 支持 tool calling，但 Deep Agents Code 不知道，请在 provider profile 中声明：

    ```toml
    [models.providers.xyz.profile]
    tool_calling = true
    max_input_tokens = 128000
    ```

    将 `max_input_tokens` 设置为 model 支持的值，以启用准确的 context length tracking 和 auto-summarization。
</Note>

provider package 必须安装在与 `deepagents-code` 相同的 Python environment 中：

```bash
# If deepagents-code was installed with uv tool:
uv tool install deepagents-code --with my_package
```

当你切换到 `my_custom:my-model-v1`（通过 `/model` 或 `--model`）时，model name（`my-model-v1`）会作为 `model` kwarg 传入：

```python
MyChatModel(model="my-model-v1", base_url="...", api_key="...", temperature=0, max_tokens=4096)
```

<Warning>
    `class_path` 会执行 config file 中指定的 arbitrary Python code。它的 trust model 与 `pyproject.toml` build scripts 相同：你控制自己的机器。
</Warning>

provider package 也可以在 `<package>.data._profiles` 中通过 `_PROFILES` dict 提供 model profiles，而不是在 `models` key 下定义。更多信息请参阅 LangChain [model profiles](https://github.com/langchain-ai/langchain/tree/master/libs/model-profiles)。

## Skills 额外允许的目录 {#skills-extra-allowed-directories}

默认情况下，当 Deep Agents Code 加载 skills 时，会验证 resolved skill file path 是否位于 standard [skill directories](/oss/deepagents/code/data-locations#skills) 之一中。这可以防止 skill directories 内的 symlinks 读取这些 roots 之外的任意 files。

如果你把 shared skill assets 存储在 non-standard location，并从 standard skill directory 通过 symlinks 引用它们，可以把该 location 添加到 containment allowlist。这 **不会** 添加新的 skill discovery location：skills 仍然只会从 standard directories 发现。

<ResponseField name="extra_allowed_dirs" type="string[]" post={["optional"]}>
    添加到 skill containment allowlist 的 paths。支持 `~` expansion。

    ```toml
    [skills]
    extra_allowed_dirs = [
        "~/shared-skills",
        "/opt/team-skills",
    ]
    ```
</ResponseField>

或者，将 `DEEPAGENTS_CODE_EXTRA_SKILLS_DIRS` environment variable 设置为 colon-separated list：

```bash
export DEEPAGENTS_CODE_EXTRA_SKILLS_DIRS="~/shared-skills:/opt/team-skills"
```

设置 environment variable 后，它会优先于 config file value。Changes 会在 `/reload` 后生效。

## 主题 {#themes}

使用 `/theme` 打开 interactive theme selector。浏览列表即可实时 preview themes，按 `Enter` 会把你的选择持久化到 `config.toml`。

Deep Agents Code 随附很多 built-in themes。默认 theme 是 `langchain`，这是一个带 LangChain-branded colors 的 dark theme。选中的 theme 会持久化到 `[ui]` 下：

```toml
[ui]
theme = "langchain-dark"
```

### 用户定义 themes {#user-defined-themes}

在 `config.toml` 的 `[themes.<name>]` sections 下定义 custom themes。每个 section 都需要 `label`（str）。如果省略，`dark`（bool）默认为 `false`；dark themes 请设置为 `true`。所有 color fields 都是 optional；省略的 fields 会根据 `dark` flag fallback 到 built-in dark 或 light palette。

```toml
[themes.my-solarized]
label = "My Solarized"
dark = true
primary = "#268BD2"
warning = "#B58900"

# Theme names with spaces require TOML quoting
[themes."ocean breeze"]
label = "Ocean Breeze"
primary = "#0077B6"
background = "#CAF0F8"
```

User-defined themes 会与 built-in themes 一起出现在 `/theme` selector 中。

### 覆盖内置 theme colors {#override-built-in-theme-colors}

如果只想微调 built-in theme colors，而不是创建新 theme，请使用 `[themes.<builtin-name>]` section。只会读取 color fields；`label` 和 `dark` 会从 built-in 继承：

```toml
[themes.langchain]
primary = "#FF5500"
```

省略的 color fields 会保留 existing built-in values。

`[themes.*]` sections 的 changes 会在 `/reload` 后生效。

### 将 themes 映射到 terminals {#map-themes-to-terminals}

如果你在不同 color schemes 的 terminals 之间切换（例如 dark iTerm 和 light Apple Terminal），可以在 `[ui.terminal_themes]` 下为每个 terminal 映射一个 theme。Deep Agents Code 会匹配 shell 的 `TERM_PROGRAM`，并自动应用 mapped theme：

```toml
[ui.terminal_themes]
"Apple_Terminal" = "langchain-light"
"iTerm.app" = "langchain"
```

在 `/theme` picker 中按 `T`，可以为当前 terminal 保存 highlighted theme；也可以运行 `echo $TERM_PROGRAM` 找到 terminal identifier，并手动添加。

<Accordion title="高级：picker shortcuts、解析顺序和 terminal identifiers" id="advanced-picker-shortcuts-resolution-order-terminal-identifiers">
    #### Picker shortcuts

    在 `/theme` selector 中：

    - `N` 在 display labels 和 canonical registry keys 之间切换；这些 keys 是 `[ui] theme` 和 `[ui.terminal_themes]` 接受的值。
    - `T` 会把 highlighted theme 保存到当前 `TERM_PROGRAM` 的 `[ui.terminal_themes]` 中。mapped theme 会在 picker 中标记为 `(default)`。

    #### 常见 `TERM_PROGRAM` 值

    Keys 会与 environment variable 做逐字匹配；当它们包含 dots 或 special characters 时，请在 TOML 中加引号。

    | Terminal | `TERM_PROGRAM` |
    | --- | --- |
    | Apple Terminal | `Apple_Terminal` |
    | iTerm2 | `iTerm.app` |
    | WezTerm | `WezTerm` |
    | VS Code integrated terminal | `vscode` |
    | Ghostty | `ghostty` |

    #### 解析顺序

    Deep Agents Code 每次 launch 都会按以下 precedence 解析 theme：

    1. `DEEPAGENTS_CODE_THEME` environment variable（explicit override）。
    2. 当前 `TERM_PROGRAM` 的 `[ui.terminal_themes]` mapping。
    3. `[ui] theme` saved preference（由 `/theme` 设置）。
    4. built-in default（`langchain`）。
</Accordion>

## 自动更新 {#auto-update}

Deep Agents Code 可以自动检查并安装 updates。

<Tabs>
    <Tab title="配置文件" id="auto-update-config-file">
        ```toml
        [update]
        auto_update = true
        ```
    </Tab>
    <Tab title="环境变量" id="environment-variable">
        ```bash
        export DEEPAGENTS_CODE_AUTO_UPDATE=1
        ```
    </Tab>
</Tabs>

environment variable 的优先级高于 config file。

启用后，Deep Agents Code 会在 session start 时检查 PyPI 是否有新版本，并使用检测到的 install method（uv、Homebrew 或 pip）自动升级。禁用时（default），Deep Agents Code 会显示 update hint 和对应 install command。

你也可以随时用 `/update` slash command 手动检查并安装 updates；它会 bypass cache，并 inline 报告 success 或 failure。

升级后，Deep Agents Code 会在下一次 launch 时显示 "what's new" banner，并链接到 changelog。

如果 session 期间检测到新版本，session exit 时会显示 update banner 作为提醒。

## 托管 deployments {#managed-deployments}

[install script](https://github.com/langchain-ai/deepagents/blob/main/libs/cli/scripts/install.sh) 支持以 root 身份运行，面向 Kandji、Jamf 等 macOS MDM tools，这些 tools 通常会在 minimal root environment 中执行 scripts。

当 `id -u` 为 `0` 时，script 会：

1. 解析真实 console user 的 `HOME`（通过 `/dev/console` 或扫描 `/Users` directory）
2. 每个 install step 后，把创建的所有 files `chown` 回 target user

Non-root installs 不受影响：当不是 root 运行时，所有 root-specific code paths 都会 short-circuit。

要为 managed installs 预配置 auto-update，请在 user shell profile 中设置 `DEEPAGENTS_CODE_AUTO_UPDATE=1`，或部署一个带 `[update] auto_update = true` 的 `config.toml` 到 `~/.deepagents/config.toml`。若要完全禁止 automatic updates 和 update checks，请设置 `DEEPAGENTS_CODE_NO_UPDATE_CHECK=1`。

## Hooks

Hooks 让 external programs 可以响应 Deep Agents Code lifecycle events。在 `~/.deepagents/hooks.json` 中配置 commands 后，每当 event 触发，Deep Agents Code 就会把 JSON payload pipe 到每个 matching command 的 stdin。

Hooks 会在 background thread 中 fire-and-forget 运行；它们不会阻塞 Deep Agents Code，失败也只会被 logged，不会中断你的 session。

### 设置 {#setup}

创建 `~/.deepagents/hooks.json`：

```json
{
  "hooks": [
    {
      "command": ["bash", "-c", "cat >> ~/deepagents-events.log"],
      "events": ["session.start", "session.end"]
    }
  ]
}
```

现在每次 session 开始或结束时，Deep Agents Code 都会把 event payload 追加到 `~/deepagents-events.log`。

### Hook 配置 {#hook-configuration}

config file 包含一个 `hooks` array。每个 entry 包含：

<ResponseField name="command" type="list[str]" required>
    要运行的 command 和 arguments。不做 shell expansion；如果需要，请使用 `["bash", "-c", "..."]`。
</ResponseField>

<ResponseField name="events" type="list[str]" post={["optional"]}>
    要 subscribe 的 event names。省略或留空时会接收 **all** events。
</ResponseField>

```json
{
  "hooks": [
    {
      "command": ["python3", "my_handler.py"],
      "events": ["session.start", "task.complete"]
    },
    {
      "command": ["bash", "log_everything.sh"]
    }
  ]
}
```

上面的第二个 hook 没有 `events` filter，因此会接收 Deep Agents Code emits 的每个 event。

### Payload 格式 {#payload-format}

每个 hook command 会在 stdin 上收到一个 JSON object，其中包含 `"event"` key 和 event-specific fields：

```json
{
  "event": "session.start",
  "thread_id": "abc123"
}
```

### Events 参考 {#events-reference}

#### `session.start`

agent session 开始时触发（interactive 和 non-interactive modes 都会触发）。

<ResponseField name="thread_id" type="string" required>
    session thread identifier。
</ResponseField>

#### `session.end`

session 退出时触发。

<ResponseField name="thread_id" type="string" required>
    session thread identifier。
</ResponseField>

#### `user.prompt`

interactive mode 中 user 提交 chat message 时触发。

没有 additional fields。

#### `input.required`

agent 需要 human input（human-in-the-loop interrupt）时触发。

没有 additional fields。

#### `permission.request`

一个或多个 tool calls 需要 user permission 时，在 approval dialog 前触发。

<ResponseField name="tool_names" type="list[str]" required>
    请求 approval 的 tools 名称。
</ResponseField>

#### `tool.error`

tool call 返回 error 时触发。

<ResponseField name="tool_names" type="list[str]" required>
    出错 tool(s) 的名称。
</ResponseField>

#### `task.complete`

agent 完成当前 task 时触发（streaming loop 结束且没有 further interrupts）。

<ResponseField name="thread_id" type="string" required>
    session thread identifier。
</ResponseField>

#### `context.compact`

Deep Agents Code compact（summarize）conversation context 前触发。

没有 additional fields。

### 执行模型 {#execution-model}

- **Background thread**：Hook subprocesses 会通过 `asyncio.to_thread` 在线程中运行，因此 main event loop 永远不会被阻塞。
- **Concurrent dispatch**：当多个 hooks 匹配同一 event 时，它们会在线程池中并发运行。
- **5-second timeout**：每个 command 有 5 秒 timeout。超时 commands 会被 killed。
- **Fire-and-forget**：Errors 会按 hook 捕获，并以 debug/warning level 记录。失败 hook 永远不会让 Deep Agents Code crash 或 stall。
- **Lazy loading**：config file 会在第一次 event dispatch 时读取一次，并在 session 剩余期间缓存。
- **No shell expansion**：Commands 会直接执行（不会通过 shell）。如果需要 pipes 或 variable expansion 等 shell features，请包在 `["bash", "-c", "..."]` 中。


### 安全注意事项 {#security-considerations}

Hooks 遵循与 Git hooks 或 shell aliases 相同的 trust model：任何能写入 `~/.deepagents/hooks.json` 的 user 都可以执行 arbitrary commands。这是 intentional design：

- **No command injection**：Payload data 只会作为 JSON 流向 stdin，永远不会进入 command-line arguments。`json.dumps` 会处理 escaping。
- **No shell by default**：Commands 使用 `shell=False` 运行，防止 shell injection。
- **Malformed config**：Invalid JSON 或 unexpected types 会产生 logged warnings，而不是 security issues。

<Warning>
    只添加来自你信任 sources 的 hooks。hook 拥有与你 user account 相同的权限。
</Warning>
